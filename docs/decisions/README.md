# Décisions d’architecture (ADR)

Les décisions durables sont documentées ici sous la forme
`ADR-NNN-titre.md`. Une ADR doit décrire le contexte, les options considérées,
la décision, ses conséquences et la date de révision éventuelle.

Les sujets qui ne sont pas encore tranchés doivent rester dans une RFC ou une
GitHub Discussion. Une fois la décision prise, la RFC est résumée dans une ADR
et les tâches d’implémentation sont reliées à l’epic de [ROADMAP.md](../../ROADMAP.md).

Ne pas utiliser une ADR pour recopier le backlog : une ADR explique *pourquoi*
une direction a été retenue, tandis que GitHub suit *ce qui doit être fait*.
